## 排查 "Invalid API key" 错误

用户反馈：调用对话返回 `{"error":{"message":"Invalid API key","type":"authentication_error"}}`。

### 结论：错误是本地代理发出的，不是上游服务端

该错误格式只在 `proxy_server.py` 两处发出（`_handle_chat_completions` 和 `/v1/models` handler），都是本地代理的子 API Key 鉴权失败时返回。

### 根因分析
buddyKey 格式为 `sk-h67_KlQ...`（以 `sk-` 开头）。`_authenticate` 方法第 2641 行有特殊逻辑：
```python
if token.startswith("sk-"):
    # 认为是已删除/无效的子Key，直接返回 None
    return None
```
当 `authenticate_sub_key(token)` 在子 key 池没找到匹配时，`sk-` 开头的 token 会被直接拒绝（不进入本地透传模式）。所以如果 buddyKey 没正确写入子 key 池，或鉴权缓存陈旧，就会返回这个错误。

### 加的日志
1. `proxy_server.py` `_authenticate`：
   - 打印传入 token 前12位和长度
   - 匹配成功时打印 key_id 和 label
   - `sk-` 拒绝时打印当前子Key池内容（key_id, api_key前缀, label），便于对比

2. `accounts.py` 激活写入子 key：
   - 成功写入时打印 api_key 前16位和长度
   - 已存在时打印跳过
   - 失败时打印异常堆栈（之前是 `except: pass` 吞掉错误）

### 待用户验证
运行后查看日志：
- `[激活] 已写入子API Key` —— 确认激活时 buddyKey 是否写入子 key 池
- `[_authenticate] token=...` —— 确认客户端传的 token 是否就是 buddyKey
- `[认证] 子Key不存在或已删除...当前子Key池=...` —— 对比传入 token 和池中 key

## 取消子Key池概念，改为单一 buddyKey 鉴权

用户要求：取消子Key池概念，整个系统只有一个 key 就是服务器返回的 buddyKey。

### 修改文件

1. **`proxy_server.py` `_authenticate`**：完全重写，不再查子Key池，不再有透传模式/开放模式区分。直接用 `get_machine_code()` 取 buddyKey，客户端 Bearer token 必须 == buddyKey 才通过。通过后返回虚拟 sub_key（`key_id="_buddykey_"`），仅用于日志统计。鉴权失败统一返回 401。

2. **`proxy_server.py` `_handle_chat_completions`** / `/v1/models`：删除开放模式/本地模式分支，鉴权失败直接返回 401。

### 上游转发
上游 Authorization 用 `upstream_key.get("api_key")`（上游Key池里的 buddyKey，激活时写入）。本地鉴权用 `get_machine_code()`（buddyKey）。两者是同一个值。
