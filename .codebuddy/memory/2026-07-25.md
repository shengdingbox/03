## 启动服务时自动同步配置（src/ui/pages/dashboard.py）

### 需求
用户点击"启动服务"时，根据勾选的 WorkBuddy/CodeBuddy 自动同步配置（写 models.json + 配置调试端口），不需要先点"立即配置"。

### 实现
在 `_toggle_proxy_service()` 启动服务前调用新方法 `_auto_sync_config_before_start()`：

1. 保存客户端配置（勾选状态、模型前缀等）
2. 检查勾选目标（WorkBuddy / CodeBuddy）
3. 生成配置 JSON（`_build_config_json()`）
4. 自动备份（如果勾选了自动备份）
5. 静默写入 models.json 到所选客户端目录
6. 如果勾选了 WorkBuddy，后台静默配置调试端口并重启（`_SilentWorkbuddySetupThread`）

### 与 _apply_config 的区别
| 行为 | _apply_config | _auto_sync_config_before_start |
|------|--------------|-------------------------------|
| 确认弹窗 | 有 | 无（静默） |
| 成功提示 | "配置已更新..." | 无（只写日志） |
| 调试端口 | 后台配置 + 弹提示 | 后台静默配置，只写日志 |

### 效果
用户只需点"启动服务"一个按钮，自动完成：配置同步 → 获取 BuddyKey → 启动代理服务

## 启动服务改用加载弹窗（src/ui/pages/dashboard.py）

### 需求
去掉诊断自检弹窗（逐条显示检查项的动画），换成简单的加载弹窗（旋转图标 + 提示文字），后台执行启动流程。

   - `_close_loading_dialog()` — 关闭弹窗并清理资源

2. **修改 `_toggle_proxy_service`**：
   - `_show_diag_dialog` → `_show_loading_dialog("正在启动服务...")`
   - 去掉 `_run_diag_animation` 调用，直接 `_fetch_buddykey()`

3. **修改回调方法**：
   - `_on_buddykey_done` — 所有 `_diag_title.setText` / `_close_diag_dialog` → `_close_loading_dialog`
   - `_on_service_started` — 同上
   - `_fetch_buddykey` — 调用时更新提示 "正在获取 BuddyKey..."
   - BuddyKey 写入时更新提示 "正在写入配置并启动服务..."

### 启动流程（新）

```
点击启动 → 加载弹窗"正在启动服务..."
  → 配置同步（静默）
  → 更新提示"正在获取 BuddyKey..."
  → 获取 BuddyKey
  → 更新提示"正在写入配置并启动服务..."

```

## 自动启动服务 + 统一加载提示（src/ui/pages/dashboard.py）

### 需求
1. 加载弹窗全程显示"正在启动服务..."，不显示"正在获取 BuddyKey..."等中间步骤
2. 页面打开时查询余额，余额 > 10 自动启动服务（启动服务时自动配置）

### 实现
1. **去掉中间提示**：`_fetch_buddykey` 中移除 `_update_loading_text("正在获取 BuddyKey...")`，`StartServiceThread` 前移除 `_update_loading_text("正在写入配置并启动服务...")`，全程只显示初始的"正在启动服务..."

2. **自动启动**：在 `_on_credits_done` 中，余额查询成功后检查：
   - `balance > 10` 且服务未运行
   - 满足条件则调用 `self._toggle_proxy_service()` 自动启动

### 启动流程（最终版）
```
页面打开 → 查询余额
  → 余额 > 10 且服务未运行 → 自动启动服务
    → 加载弹窗 "正在启动服务..."
    → 自动同步配置（根据勾选）
    → 获取 BuddyKey
    → 余额检查（余额为 0 拒绝启动）
    → 写入 Key + 启动服务
    → 关闭加载弹窗
  → 余额 <= 10 → 不自动启动，用户手动点按钮
```

## macOS Dock 图标优化（src/main_window.py）

### 问题
macOS 下 `.ico` 格式图标在 Dock 中显示模糊，分辨率低。

### 修复
1. **macOS 优先程序化生成 256x256 高清图标**：
   - `_generate_high_res_icon()` — 圆角矩形渐变背景（紫色）+ 白色闪电图形
   - 渐变色：`#7C3AED → #6C5CE7 → #5B4FE9`
   - 闪电多边形 + 阴影层叠
2. **`_set_dock_icon(icon)`** — macOS 专用，通过 AppKit NSImage 设置 Dock 图标
3. **`_load_app_icon()`** 重构：
   - macOS：生成高清图标 + 设置 Dock
   - Windows/Linux：优先加载 `.ico`，降级为程序化生成
   - 支持 Nuitka 和 PyInstaller 两种打包模式
