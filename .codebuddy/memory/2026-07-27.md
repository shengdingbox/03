# 2026-07-27

## macOS 不显示控制台（终端窗口）

**问题**: macOS 上 Nuitka `--onefile` 打包的纯可执行文件，双击运行时会弹出终端/控制台窗口。

**解决方案**: macOS 构建改用 `--macos-create-app-bundle`，生成标准 `.app` bundle，双击运行不会弹出终端。

### 修改内容

1. **`.github/workflows/build.yml`** — Intel + ARM 两个构建均修改：
   - 构建命令添加 `--macos-create-app-bundle --macos-app-icon=assets/icons/icon.icns`
   - 新增 "Generate .icns icon" 步骤：用 Pillow 从 `app.ico` 提取 256x256 PNG → `sips` 生成多尺寸 iconset → `iconutil` 生成 `.icns`
   - 新增 "Install icon tools" 步骤：`pip install Pillow`
   - 产物从 `dist/BuddyTool`（裸可执行文件）改为 `dist/BuddyTool-Intel.zip` / `dist/BuddyTool-ARM.zip`（压缩 `.app` bundle）
   - 新增 "Compress app bundle" 步骤：`zip -r -y BuddyTool-*.zip BuddyTool.app`
   - 架构验证路径更新为 `dist/BuddyTool.app/Contents/MacOS/BuddyTool`

2. **Release 说明** 更新：
   - macOS 产物文件名改为 `.zip`
   - 安装说明改为"解压后获得 `BuddyTool.app`，双击运行"
   - CLI 使用方式更新为 `BuddyTool.app/Contents/MacOS/BuddyTool help`

### 注意事项
- `--macos-create-app-bundle` 与 `--onefile` 兼容（onefile 可执行文件放在 `Contents/MacOS/` 下）
- macOS 没有类似 `--windows-console-mode=disable` 的选项，`.app` bundle 是隐藏终端的标准方式
- `main.py` 中 macOS Dock 激活代码无需修改，与 `.app` bundle 兼容
- `main_window.py` 中图标为程序化生成，不依赖文件路径，无需修改

## 添加备用域名 api.shengdingit.com

**需求**: 主域名 `buddy.shengdingit.com` 无法连接时，自动切换到备用域名 `api.shengdingit.com`。

### 修改内容

1. **`src/utils/_obfuscate.py`** — 新增 `SERVER_BASE_FALLBACK` 加密条目（`https://api.shengdingit.com/api`，salt=0x4E）

2. **`src/utils/ssl_pinning.py`** — `_PINNED_HOSTS` 集合增加 `api.shengdingit.com`，`install_pinning()` 同时为两个域名 mount adapter

3. **`src/utils/server_api.py`** — 核心改动：
   - 新增全局变量 `_active_base`（当前活跃域名）和 `SERVER_BASE_FALLBACK`
   - 新增 `_post_with_failover(path, payload, timeout)` 方法：先尝试当前活跃域名，网络层异常（ConnectionError/Timeout/SSLError）时自动切换到另一个域名重试
   - 所有 API 函数（`get_credits`, `redeem`, `get_buddykey`, `check_version`, `get_models_list`, `report_usage`）全部改用 `_post_with_failover`，去除了重复的 try/except 和直接 `_session.post` 调用
   - 清理了重复的 import 和 `_NO_PROXY` 变量（已用 `_session.trust_env = False` 替代）
   - 触发切换的异常类型：`ConnectionError`, `Timeout`, `SSLError`（不包含 HTTP 状态码错误）

### 故障转移逻辑
- 首次请求用主域名 → 网络异常 → 自动用备用域名重试
- 一旦切换到备用域名，后续请求优先用备用域名（直到备用域名也故障才切回主域名）
- 非网络层异常（如解密失败、HTTP 4xx/5xx）不触发域名切换
